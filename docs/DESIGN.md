# Sidepad for Windows 设计文档

版本：0.2
更新时间：2026-07-17
状态：实现中

设计与实现的逐项映射参见 [`DESIGN-CODE-MAP.md`](DESIGN-CODE-MAP.md)。

## 1. 产品概述

Sidepad 是一个常驻 Windows 屏幕边缘的轻量内容工作台。它平时隐藏，不占用任务栏和桌面空间；鼠标触碰屏幕边缘时快速展开，让用户无需切换和整理多个窗口，即可访问网页、笔记和常用文档。

产品体验参考 macOS Slidepad 的“随手即用”，但采用更稳定的失焦隐藏规则，并将内容范围扩展为：

- Chromium 网页
- 本地文本与快速笔记
- PDF 和常见图片
- PPTX、DOCX、XLSX
- 其他本地文件的快捷入口

## 2. 设计目标

### 2.1 核心目标

1. 触达成本低：鼠标移动到屏幕边缘即可唤醒。
2. 视觉干扰低：收起时只保留极窄触发区域。
3. 内容优先：展开后将绝大部分空间交给网页或文档。
4. 操作一致：网页、笔记和文件使用统一的内容项模型。
5. 安装即用：安装包自带 Chromium 和文档解析能力。
6. 双屏可靠：只在 Windows 主显示器激活，避免副屏边缘和跨屏移动误触。

### 2.2 非目标

- 不替代完整的 Chrome 浏览器。
- 不提供完整的 Office 编辑能力。
- 不承诺 100% 还原所有 PPTX 动画、宏和复杂图表。
- 不直接修改用户原始 Office 文件。
- 首版不支持旧式二进制 `.ppt`、`.doc`、`.xls` 的内嵌解析。

## 3. 用户场景

### 场景 A：快速查询

用户正在写文档，将鼠标移到屏幕右侧，Sidepad 以预览态展开。若没有点击 Sidepad 就移回原工作区，面板自动隐藏；若点击 Sidepad 进入交互态，鼠标移出后继续显示，直到用户点击原文档窗口，Sidepad 因失焦自动隐藏。

### 场景 B：常用网页

用户将 ChatGPT、Notion、项目管理工具等固定到首页。打开后网页保持登录会话，下次可直接恢复。

### 场景 C：参考资料

用户将 PDF、图片或 PPTX 拖入 Sidepad。文件以快捷卡片出现，点击后在内容区预览。

### 场景 D：双显示器

用户在双屏环境工作。副屏边缘不触发 Sidepad；只有主屏右边缘可以展开面板，显示器配置变化后触发区自动迁移到新的主屏。

## 5. 窗口与自动隐藏

### 5.1 状态模型

```text
隐藏
  └─ 鼠标进入触发区 140ms
       ↓
正在展开（180ms）
       ↓
预览态（不抢焦点）
  ├─ 鼠标停留：保持
  ├─ 鼠标离开：延迟收起
  └─ 点击面板 / 面板获得焦点
             ↓
交互锁定态
  ├─ 鼠标离开：保持展开
  ├─ 窗口失焦 480ms：收起并解锁
  └─ Esc / 收起按钮：立即收起并解锁
       ↓
正在收起（180ms）
       ↓
隐藏
```

### 5.2 隐藏状态

- 主面板完全移到工作区右侧并隐藏。
- 仅 Windows 主显示器保留 12px 宽的透明/紫色触发窗口。
- 触发窗口始终置顶，但不获取键盘焦点。
- 外侧屏幕边缘可使用全高触发区。
- 两块屏幕相邻的接缝只使用居中的短触发区，降低跨屏误唤醒。

### 5.3 展开状态

- 面板宽度为显示器工作区的约 42%，保持轻量、不遮挡主要工作区。
- 最小宽度 520px，最大宽度 680px；足以容纳网页、笔记和基础 Office 预览。
- 面板从右向左使用 ease-out 动画展开。
- 面板始终在 Windows 主显示器右侧展开。
- 悬停唤醒使用 `showInactive`，不主动抢走当前应用焦点。
- 用户点击面板或面板实际获得焦点后进入交互锁定态；此后保持置顶，切换焦点后自动收起并解锁。
- 右上角关闭按钮表示退出应用：必须同时销毁主窗口和所有边缘触发窗口，并结束进程，不允许留下不可唤醒的后台窗口。

## 6. 双屏和多屏规则

1. 应用只为 Windows 主显示器创建一个触发窗口，副屏不提供触发入口。
2. 主面板始终在主显示器展开，不跟随鼠标迁移到副屏。
3. 显示器新增、移除、旋转、缩放、分辨率或主屏设置变化时，立即重建触发窗口并重定位面板。
4. 主显示器右侧没有相邻屏幕时，使用全工作区高度的 12px 触发区。
5. 主显示器右侧存在相邻屏幕时，将该边缘视为共享接缝。
6. 共享接缝使用居中的 320×12px 触发条，并加入 140ms 防误触延迟。

## 7. 界面设计

### 7.1 设计原则

- 简洁：默认隐藏文字说明和次要控制项。
- 内容优先：避免传统浏览器的大型标签栏和书签栏。
- 轻量：使用浅色磨砂背景、柔和阴影和有限强调色。
- 一致：所有内容类型都能从统一卡片进入。
- 渐进披露：只有打开网页时才显示网页导航工具。

### 7.2 首页布局

- 左侧：62px 窄图标轨道。
- 顶部：胶囊形搜索框，可输入网址或关键词。
- 中部：快捷内容卡片网格。
- 卡片：半透明浅色背景、小图标、底部名称。
- 最后一张卡片固定为“添加内容”。

当前预览：

![Sidepad 当前界面](../sidepad-preview.png)

### 7.3 内容轨道

- 品牌按钮：34×34px。
- 添加按钮：40×40px。
- 内容入口：44×44px。
- 当前项使用 3px 紫色短线标识。
- 内容名称通过系统 tooltip 显示，不常驻占用空间。
- 底部保留管理与收起按钮。

### 7.4 网页视图

- 顶部内容标题栏：48px。
- 浏览工具栏：45px。
- 提供后退、前进、刷新、地址栏、收藏和外部浏览器打开。
- 网页使用独立持久分区 `persist:sidepad`，保留 Cookie 和登录会话。
- 网页内容由 Electron 自带 Chromium 渲染，不依赖本机 Chrome。
- 默认搜索使用 Bing，用户输入完整网址时直接访问目标站点。
- 主页面加载失败时显示 Chromium 错误原因，并提供重新加载和默认浏览器打开入口。
- 网页请求打开新窗口时，不创建隐藏弹窗；HTTP/HTTPS 地址在当前网页视图中继续打开。
- 网页请求使用去除 Electron 产品标识的 Chromium User-Agent，提高常见网站兼容性。
- 应用壳和 WebView 使用剩余可读宽度，不设置大于面板的最小宽度；响应式网页应在窄面板内重新排版，非响应式网页的横向滚动限制在 WebView 内部。
- WebView 在非网页标签下仍保持与内容区相同的布局尺寸，只切换可见性，避免 Electron 以默认 300×150 视口初始化后拉伸网页。
- 网页加载后检测实际内容宽度；响应式网页保持原样，横向溢出时先移除最小宽度并限制顶层内容到窄栏，保持 100% 字号。只有无法重排的复杂页面才降低 WebView 缩放，最低 45% 并保留 3% 右侧安全边距；新导航会重置并重新计算。

### 7.5 笔记视图

- 使用无干扰的纸张式编辑界面。
- 内容输入时自动保存。
- 顶部只显示自动保存状态和字数。
- 笔记存储在应用本地数据中。

### 7.6 文档视图

| 格式 | 处理方式 |
|------|----------|
| TXT、MD、JSON、CSV、LOG | 内嵌文本预览 |
| PNG、JPG、GIF、WebP、SVG | Chromium 图片预览 |
| PDF | Chromium PDF 预览 |
| DOCX | 内置 `docx-preview` 排版 |
| PPTX | 内置 `pptx-preview`，按内容区实际宽度连续纵向展示全部幻灯片 |
| XLSX | 内置 `ExcelJS` 表格预览 |
| PPT、DOC、XLS | 显示不支持提示，可尝试交给系统关联应用 |

## 8. 添加内容

添加弹窗提供三种入口：

1. 网页：填写名称和 URL。
2. 文本笔记：即时创建并进入编辑。
3. 本地文件：使用系统文件选择器，可多选。

用户也可以将文件直接拖放到主面板。拖动期间显示全屏虚线提示层，松开后添加为快捷内容。

## 9. 数据模型

统一内容项结构：

```js
{
  id: "UUID",
  type: "web | note | file",
  name: "显示名称",
  url: "网页地址",
  content: "笔记或小型文本文件内容",
  path: "本地文件绝对路径",
  previewUrl: "受控本地预览地址",
  ext: "文件扩展名",
  size: 12345,
  color: "#7566ec"
}
```

### 持久化规则

- 内容列表、激活项和笔记内容保存在本地。
- 网页登录数据保存在 Electron 持久分区。
- 本地文件只保存路径，不复制、不上传、不修改。
- 文件丢失或移动后，界面显示“找不到文件”，用户可从列表移除。

## 11. 安全设计

- 渲染进程启用 `contextIsolation`。
- 关闭渲染进程 Node.js 集成。
- 预加载层只暴露有限白名单接口。
- 本地文件必须经文件选择或重启后的路径校验授权。
- 自定义协议只返回已授权的文件。
- 外部链接只允许 `http` 和 `https`。
- 网页新窗口默认在当前网页视图继续打开；用户可通过顶栏按钮主动交给系统浏览器。
- Electron 使用已修复已知安全公告的版本。
- Office 解析依赖通过 npm 审计，当前为 0 个已知漏洞。

## 12. 自包含安装

Windows 安装包包含：

- Electron 运行时
- Chromium
- 应用 HTML/CSS/JavaScript
- PPTX、DOCX、XLSX 解析组件
- NSIS 安装程序

用户不需要额外安装：

- Chrome
- Microsoft Office
- LibreOffice
- Node.js
- Java 或 Python

构建产物包括 NSIS 安装版和 portable 便携版；CPU 架构由构建任务决定：

- `npm run dist` / `npm run dist:win:x64`：默认 Windows x64
- `npm run dist:win:arm64`：可选 Windows ARM64

正式发布以 Windows x64 为默认目标。开发机可以是 macOS 或 Windows，但验收环境必须包括 Windows 10/11 x64。

## 14. 无障碍和易用性

- 所有纯图标按钮提供 `title` 或可访问名称。
- 键盘可访问地址栏和表单。
- 仅悬停唤醒且尚未点击时，鼠标移出会延迟收起；点击进入交互锁定态后，鼠标移出不会隐藏。
- 交互锁定态窗口失焦后延迟 480ms 收起并解锁，避免焦点短暂抖动。
- 打开弹窗时取消自动收起计时。
- 文件解析失败时显示具体错误和文件夹定位入口。
- 网页加载失败时显示错误代码、重试按钮和系统浏览器入口。

## 15. 已知限制

- PPTX 渲染不保证完整支持复杂图表、公式、宏、视频和动画。
- PPTX 预览使用完整可读区域，面板尺寸变化时重新按实际宽度排版；多页通过内容区纵向滚动浏览。
- 系统文件选择器打开期间暂停失焦隐藏，选择或取消后恢复 Sidepad；成功渲染的 PPTX 在当前会话缓存，切换标签后可即时恢复。
- DOCX 渲染可能与 Word 的字体换行存在差异。
- XLSX 首版侧重数据查看，不实现 Excel 公式计算和完整样式还原。
- `.ppt`、`.doc`、`.xls` 旧式二进制格式不提供内嵌预览。
- 当前默认停靠右侧；左侧停靠属于后续设置项。
- Windows 应用尚未配置正式代码签名证书和品牌图标。

## 17. 验收标准

- 只有 Windows 主显示器右侧边缘可唤出面板，副屏边缘不触发。
- 外侧边缘使用全高 12px 触发区；共享接缝使用居中 320×12px 触发区，普通跨屏动作不应频繁误触。
- 未点击的悬停预览在鼠标离开后能可靠隐藏；点击进入交互态后鼠标离开保持展开，点击其他窗口造成失焦后可靠隐藏。
- 点击关闭按钮后主窗口、边缘触发窗口和应用进程均退出。
- 网页登录会话可持久保存。
- 笔记输入可自动保存。
- PDF、图片、PPTX、DOCX、XLSX 能在无 Office 环境中打开。
- 三页及以上 PPTX 可在完整内容区连续纵向浏览，且不出现横向裁切。
- 安装版在全新 Windows 10/11 中无需额外运行时即可启动。
- 应用生产依赖没有已知高危漏洞。
